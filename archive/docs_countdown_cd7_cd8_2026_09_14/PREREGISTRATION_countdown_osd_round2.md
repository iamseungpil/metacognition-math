## 0. 라운드 1은 왜 실패했나 (이 문서의 존재 이유)

500문제 × 8롤아웃 × 씨앗 4개 기준, **학습 안 한 원본과 네 팔이 전부 같았다.**

| | 정답률 | 구조율 |
|---|---|---|
| 원본(무학습) | 15.94 ±0.75 | 6.00% |
| A 대조 | 15.92 ±0.61 | 6.28% |
| B 진짜 | 16.16 ±0.95 | 5.85% |
| G 가짜 | 15.77 ±0.46 | 5.71% |
| C 부호곱 | 14.97 ±0.18 | 5.63% (t=−2.95, **유의하게 나쁨**) |

원인 두 가지를 **측정으로** 확정했다.

1. **학습 신호 소실.** 그룹의 57~58% 가 8롤아웃 전원 오답 → GRPO 어드밴티지가 정확히 0.
   학습 후에도 안 줄었다(56.8 → 53.6~56.2%).
2. **계기 포화.** PMI-shift 의 within-group AUC 가 전 팔·전 스텝에서 0.517~0.555.
   수학 세대에서 "치명적"이라 선언한 0.539 와 같은 대역이다.

②는 **라운드 1 사전등록이 논증으로만 통과시킨 유일한 항목**이었다(§2: "수학의 규칙기반
오답은 포화됐다(AUC 0.539) — 그 결함이 여기엔 없다"). 문서 전체에서 AUC 숫자는 그
하나뿐이고, Countdown 에 대해서는 **한 번도 측정하지 않았다.**

### 포스트모템 — 오류의 이름

- **층 1: «잘 정의됨»을 «타당함»으로 오인.** 사전 검사는 전부 배관 검사였다(오답 토큰
  차이 300/300, NaN 6.7%, 항별 std). 계기의 **감도**만 논증으로 대체됐다. 더 아픈 것은
  그 감도를 재는 절차를 **이미 갖고 있었다**는 점이다 — 수학에서 0.457 을 그 절차로 쟀다.
- **층 2: 회의주의 예산의 비대칭.** «가짜 대조군이 이기면 전부 폐기»(G 팔)까지 사전등록해
  **결과 수준**의 자기기만은 정교하게 막았다. 그런데 모든 처치가 의존하는 **계기 수준**에는
  수사적 면제를 줬다. 그리고 결정타: `meta_outcome_discrimination` 의 docstring 에
  «AUC ~0.5 면 B/C/F 의 널은 신호 없음이다» 라는 **판독 규칙이 적혀 있었고**, 그 AUC 를
  매 스텝 찍고 있었다. 실험을 죽일 데이터가 처음부터 쌓였는데 **그 데이터에 행동할 권한을
  가진 코드가 없었다.** 모니터링이 회로차단기가 아니라 사후 고고학이 됐다.

**교훈(이 문서 1조):** 처치를 정의하는 모든 보상 항은 ⑴ **출시 전 측정된** 타당성 수치와
⑵ **중단 규칙이 실행 코드로 달린** 학습 중 감시를 요구한다.

## 2. 처치 — OSD (Outcome-Signed Surprisal Drop)

```
메타 미발화 또는 형식 위반  →  R_osd = 0

발화 시:  t0 = <meta> 시작,  t1 = </meta> 끝
          W  = 응답 t1+1 .. t1+L,  L = min(200, \boxed 끝까지)

Δcert_i = (1/|W|)·[ logP(W | prompt ⊕ 응답[..t1])      # 메타 포함
                  − logP(W | prompt ⊕ 응답[..t0)) ]    # 메타 구간만 제거

R_osd(i) = y_i · clip(Δcert_i / 0.366, −1, +1),   y_i = +1(정답) / −1(오답)
```

**왜 이 형태인가.** PMI-shift 는 «남이 준 정답식»에 대한 믿음을 **1토큰 폭**으로 쟀다
(실측 300/300 이 1토큰 차이). 연구 질문은 «모델 **자신의** 사고가 불확실 → 확실로 가는가»
이므로, 대비축을 «증인 vs 오답»에서 **«메타 있음 vs 없음»** 으로 바꾸고 대상을 **자기 궤적**
으로 옮긴다. 길은 고정하고 조건만 바꾸므로 내용 변화와 확실성 변화가 교락되지 않는다.

**왜 결과 부호인가.** 확신 자체는 미덕이 아니다. y 를 곱하면 네 사분면이 전부
calibration 방향이 된다: 확신↑정답 +상 / 확신↑오답 −벌(과신) / 확신↓정답 −벌 /
확신↓오답 +상(정직한 불확실성). 부수 효과로 **전원 오답 그룹에서도 그룹 내 분산이 남아**
라운드 1 의 근본 원인(57% zero-advantage)에 부분 해독제가 된다.

**방어선:** 누출 가드(메타·W 가 토큰 8-그램 공유 또는 메타가 최종 수식 포함 → Δ:=0,
실측 차단 11~13건/스텝) · W 길이 정규화 · Δ=None(못 쟀다)은 **fail-loud 예외**,
NaN(비유한)만 0 fail-closed.

## 3. 출시 전 관문 — **통과했다** (이 라운드의 1조)


## 4. 학습 중 중단 규칙 — **실행되는 코드로**

`verl_sdc._osd_demote_check`. 매 스텝 **unsigned** Δcert 의 within-group AUC 를 재고
(signed 는 y=r_corr 라 AUC 가 항진명제이므로 unsigned 로 잰다):

```
step ≥ 15  이고  최근 10스텝 rolling 평균 AUC < 0.58
   →  w_meta := 0 으로 자동 강등, [COUNTDOWN][OSD-DEMOTE] 로그, 이후 스텝은 처치로 세지 않는다
```

동작 검증 완료(14스텝까지 무반응, 15스텝 발동). 강등은 **다음 스텝부터** 적용한다 —
이미 뽑은 롤아웃의 보상을 소급 변경하면 그 스텝의 어드밴티지가 정책과 어긋난다.

## 6. 사전 예측 (결과를 보기 전에 적는다)

- **P1 (주가설).** OSD 는 A 대비 구조율(rescue_rate)을 올린다. 이것이 연구 질문
  «틀려도 점검해서 정답까지 가는가» 의 직접 지표다.
- **P2 (반증).** G 가 A 를 이기면 «아무거나 보상하면 오른다» 이므로 **전부 폐기**한다.
  라운드 1 에서 이 조건은 통과했다(G−A t=−0.39).
- **P3 (기제).** OSD 의 효과가 있다면 «확신에 차서 틀린» 롤아웃의 비율이 줄어야 한다.
  이 지표를 학습 중 상시 계측한다.
- **P4 (무효).** 25스텝에서 세 팔이 구분되지 않고 원본과도 같으면, 걸음 수가 아니라
  다른 원인이다(라운드 1 의 «기울기는 양수지만 유의하지 않고, 전원오답 비율은 오히려
  증가» 패턴을 재확인하는 것).

## 7. 알려진 한계 — 미리 적는다

1. **순수 GRPO 팔이 없다.** 세 팔 모두 형식 점수 0.35 로 메타 발화를 요구한다. 따라서
   «메타인지 > 순수 GRPO» 는 주장할 수 없다. 주장 가능한 것은 «메타 발화를 전제한
   상태에서 내용 채점의 추가 효과» 뿐이다.
2. **지시문 복사.** `new` 프롬프트에서 메타 본문이 프롬프트의 지시문을 그대로 베끼는
   사례가 관측된다(판박이율 2.0~7.0%, 10걸음 평균 4.0%). `shot` 이 원래 이걸 막는
   장치였으나 계기를 역전시켜 채택 불가였다. **판박이율을 매 스텝 감시**하고 5% 를
   지속 초과하면 중단한다.
3. **훈련 씨앗 부족 가능성.** §5 참조.
4. **`OSD_C` 는 A반 10걸음에서 잡았다.** 학습이 진행되며 Δ 분포가 이동하면 정규화가
   다시 어긋날 수 있다. `dcert_abs_p90` 을 매 스텝 로그에 남겨 사후 확인 가능하게 한다.
5. **★«말한 확신»과 «실제 또렷함»은 다른 양이다 (0826 03:30 관측 후 추가).**
   OSD 의 docstring 은 «Δcert<0 & 오답 → 상(정직한 불확실성)» 이라고 적었는데, 이는
   «의심을 표한다» 를 «Δcert 가 낮다» 와 동일시한 것이다. **실측은 그 둘이 무관하다:**

   | 메타가 선언한 confidence | n | Δcert 평균 |
   |---|---|---|
   | 낮음 (≤0.4) | 6 | **+0.604** |
   | 높음 (≥0.8) | 9 | **+0.549** |

   관측 사례: `conf=0.2 · dec=redirect · shift=+2.250 · 오답` — 「전부 더하기는 목표에
   못 닿을 것 같다」는 **정직하고 이른(응답 4% 지점) 방향 전환**인데, 그 선언이 뒤 궤적을
   크게 또렷하게 만들어 Δcert 가 +2.25 였고, 오답이므로 **R_osd = −1.0(최대 벌점)** 이다.

   즉 OSD 는 «표명된 확신» 이 아니라 «궤적의 예측가능성» 을 잰다. **좋은 방향 전환도
   Δ 를 올리므로, 그 전환이 결국 틀리면 벌을 받는다.** 이것을 결함으로 볼지 의도로 볼지는
   해석의 문제다 — 「방향을 확신 있게 정했는데 그 방향이 틀렸다」는 궤적 수준의 calibration
   실패로 읽을 수도 있다. **이 라운드에서는 공식을 바꾸지 않고**, 대신
   `conf` 와 `Δcert` 의 상관을 매 스텝 로그에 남겨 사후 판단이 가능하게 한다.
   표본 15개짜리 관측이므로 더 모아야 한다.

6. **관문은 원본 모델에서 쟀다.** 학습된 정책에서 AUC 가 유지되는지는 §4 의 학습 중
   감시가 답한다. 그것이 강등 규칙을 둔 이유다.

## 8. 레거시 잔재 (라운드 1 에서 이월, 학습에 영향 없음 확인)

`reward_loop_score` 가 매 배치 옛 채점기를 돌려 ≈ −1.2 를 만든다. `token_level_rewards`
는 본 헤드가 덮어쓰므로 학습에 영향 없음을 확인했다(`critic/rewards/mean` = 헤드값,
소수점 7자리 일치). 제거는 이 라운드 종료 후로 미룬다 — 라운드 중 코드 변경은
«팔마다 코드가 달랐다» 를 만든다.

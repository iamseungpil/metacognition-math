## Does any ruler qualify as an "exploration-timing" signal?

No. An exploration-timing ruler must (i) prefer the good move when it opens a new, not-yet-tried family while the prefix is stuck, (ii) do so without knowing the answer path, and (iii) track downstream success. Every ruler that shows good>bad does so via the answer path: osd / dhat_T1_* / inv_* condition on W or on a hint containing the witness string, and their entire separation is the good `next:` line matching W's first line (0.943) or its operator (niw0 reversal to 0.395/0.364 when the bad move carries the witness operator). The only teacher that does not see the answer path (T2, failed-attempts hint) is null on meta tokens (0.487/0.497), and its post64 variant is positive only in niw1&stuck (0.712) where it is a 0.41-correlated residual of osd, i.e. it too rewards matching the answer path, not opening a new direction. Within niw0&stuck, the stratum where "new direction while stuck" would matter, T2_post64 is 0.484 and T2_sent is a sign-flipping repeat detector of the hint list. The "stuck" advantages for osd/inv (0.820/0.823) are composition: stuck sites echo the witness first step 0.557 vs healthy 0.304. The pmi_shift family (0.593 niw0, 0.644 niw0&healthy, null in stuck 0.499/0.508) is the only one not driven by niw, but it is decoy-vs-gold PMI, is null exactly in stuck sites, and has rho ~0.05 with dsucc. So the dataset contains no demonstrated exploration-timing ruler; the one substantive non-null signal ("bad move is a large product / carries the wrong operator") is a move-surface prior, not timing.

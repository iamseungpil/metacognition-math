## B. 실제로 얹히는 크레딧 크기

`verl_sdc._math_add_revision_advantage` (4,136–4,242행):
```
cap = cap_mult · (Σ|adv|·mask / Σmask)      # 배치 «평균 |답 어드밴티지|» × MATH_REV_CAP_MULT
adv[i, t0:t1] += clip(c_i, ±cap)            # 중심화 없음, 첫 박스 끝 → 마지막 \boxed 시작
```
- `dcpo_rev_mass_share=0` (로그 `mass_share_target=0.0000` 전 스텝) → 질량-몫 모드 **꺼짐**, `scale_s=1`.
- **거의 모든 credit 행이 cap 에서 잘린다**: `clipped_rows == credit_rows` (38스텝 중 26스텝 정확히 일치,
  나머지도 차이 1~3). PMI 보상 범위는 clip 2.0 + save 1.0 = 최대 3.0 이고 cap ≈1.6~1.9 이므로
  **PMI 크기 정보가 거의 전부 버려지고 부호만 남는다** — 사실상 ±cap 이진 크레딧이다.
- 토큰당 크기: step1 cap=1.8853, 같은 배치 mean|adv|=0.628, max|adv|=2.475 →
  **구간 토큰 하나가 전형적 답 어드밴티지의 3배, 최댓값의 76%** 를 받는다(작지 않다).
- 배치 질량 몫(닫힌형 `cap_mult · zone_tokens / (512 · resp_len)`, cap 이 약분):
  **v2 mean 2.64% / median 2.45% / 범위 0.09–5.48%** (v1: 0.28% / 0.23% / 0.01–1.45%).
  step1 실측 로그 `mass_share_realized=0.041315` = 3×31,328/(512×4,443) ✓.

### 부호 일관성 — 「save +, derail −」가 아니다
`_compute_revision_rmeta` 앵커 `gold_x`: `if answers_equivalent(gold, x): skipped_anchor; continue`
(5,027–5,032행). **첫 답이 정답인 행은 전부 탈락**하므로 «정답→오답(r→w) derail» 행은
구조적으로 **크레딧을 한 번도 받지 않는다**. HABIT_vs_PMI_0919 의 지적 확인.
그러므로 음수 크레딧을 받는 행은 **오직 «첫 답 오답 + 구간 중 믿음이 gold 에서 decoy 로 반전»**
뿐이고, 그 양은 credit 행의 2.0~8.1%(late 8.1%)다. 나머지 92~98% 는 +cap.
→ 처치는 «두 방향 신호»가 아니라 **거의 단방향 보너스**이며, 실제 파손(r→w)에는 손을 못 댄다.

## E. 해석 — 크레딧이 예산을 넘어 행동을 바꿨다는 증거가 있는가

**거의 없다.** 등예산에서 정확도 차이는 0(+0.06pp, CI 0 포함)이고, 0 을 배제하는 유일한 «행동»
변화는 (a) 모든 버킷에서 수정 빈도가 내려간 것 — 그런데 이 하락은 outcome-only 대조군에서도
같은 크기로 일어나며(WHY_NO_GAIN §6: oo30 −1.20pp vs PMI −1.02pp) 세 팔의 entropy 기울기가
−0.0025~−0.0033 으로 같다 — 와 (b) 파손(r→w)의 선택적 소멸, 특히 «마커 없는 118자 꼬리» 30→3 이다.
(b) 는 크레딧에 고유할 수 있지만 **크레딧 설계가 그것을 벌 수 있는 구조가 아니다**(B: gold_x 가
r→w 행을 전부 탈락시킨다). 남는 해석은 «RL 일반의 자기일관성 강화가 꼬리를 깎았다»이다.
가장 유력한 기계적 이유 세 가지:
1. **거의 모든 크레딧 행이 cap 에서 잘려 PMI 크기가 버려진다** — `clipped_rows == credit_rows`
   (38스텝 중 26스텝 정확 일치). 학습이 보는 것은 «구간이 있었나 + 부호» 뿐이라, 좋은 수정과
   평범한 수정이 같은 값을 받는다. cap_mult 를 3배 올린 것은 이 이진 값을 3배 키운 것에 불과하다.
2. **크레딧이 사실상 단방향이고 실제 파손에 닿지 않는다** — `gold_x` 는 첫 답 정답 행을 전부
   탈락(skip_anchor)시켜 r→w derail 행에 한 번도 값을 주지 않는다. 음수를 받는 행은 credit 행의
   2.0~8.1% 뿐. «좋은 메타인지만 골라 키운다»가 아니라 «이미 오답이던 행에 보너스»다.
3. **표적 질량이 크레딧 질량의 3배인데 크레딧은 거기에 안 간다** — 크레딧은 배치의 2.64%(행 10.4/512)
   에 얹히는데, 고쳐야 할 버킷(hedge 하고도 답 안 바꾼 행)은 12k 에서도 **17.0%→17.2%** 로 요지부동이고
   그 대신 «같은 답 재확인» 행이 학습 중 +1.15/step (t=4.02) 로 늘었다. 크레딧은 **수정 구간이 이미
   존재하는 행만** 볼 수 있어 «구간을 만들지 않는 행»에는 구조적으로 무력하다.

## F. 함의 (짧게)
- 0919 의 «노출 부족» 처방은 이행됐고 **반증됐다**. cap_mult 를 더 올리는 축은 닫는 것이 맞다.
- 8k 기반 성능 주장(+1.17pp)은 **예산 인공물**이다. 이후 모든 rev 팔 판정은 12k 등예산으로.
- 살아 있는 표적은 하나: **구간을 만들지 못하는 행**(hedge·재확인 17%). `MATH_REV_CONFIRM=1`
  (이미 배선됨, v2 는 0)이 유일하게 그 행에 닿는 레버다.
- v2 는 step 38/50 진행 중 — 잔여 12스텝이 위 결론을 뒤집을 여지는 rev_rate 기울기 t=−0.53 기준 낮다.
